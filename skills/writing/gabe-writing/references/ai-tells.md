# AI tells, worst first

The taxonomy of patterns that make writing read as generated. Ordered by how often they show
up in agent output, not by how bad each one is in isolation.

Origin: the public tropes.fyi taxonomy, plus additions from practitioner threads.

## The four that dominate agent output

### 1. Negative parallelism: "It's not X, it's Y"

The single most commonly identified tell, and at volume it insults the reader. Variants:

- Causal: "not because X, but because Y"
- Dash dismissal: "X, not Y"
- Cross-sentence reframe: "The question isn't X. The question is Y."

One per piece can land. Ten is a signature.

Fix: state the true thing and delete the negated half. The negated half is almost always a
strawman invented to knock down.

### 2. Bold-first bullets

Every bullet opening with a bolded phrase. Named specifically as a model tell. Status reports
are usually wall-to-wall this.

Fix: bold the one thing that must survive skimming. Usually that is zero or one item per
message.

### 3. Em dash addiction

A human writing quickly uses two or three per piece. Models use twenty.

Fix: comma, or split the sentence.

### 4. Short punchy fragments as standalone paragraphs

"Not stuck, just slow." Manufactured emphasis with an inhuman rhythm.

Fix: write the full sentence, or fold it into the neighbouring one.

## The rest of the list

Self-posed rhetorical questions ("The X? A Y.") - anaphora, repeated sentence openings -
tricolon abuse - "it's worth noting", "importantly", "notably" - trailing "-ing"
pseudo-analysis ("highlighting its importance") - false ranges ("from X to Y" with no real
middle) - magic adverbs (quietly, deeply, fundamentally, arguably) - delve, leverage, robust,
streamline, harness - tapestry, landscape, paradigm, ecosystem - "serves as" for "is" -
"here's the kicker" - grandiose stakes inflation - "let's break this down" - vague attribution
("experts say") - invented concept labels, made by appending paradox, trap, creep, or divide
to a domain word and then using it as established - unicode arrows and smart quotes - fractal
summaries - dead metaphors - one point diluted across several sentences - "in conclusion" -
"despite these challenges".

## The rule at the bottom of the source

> Any of these patterns used once might be fine. The problem is when multiple tropes appear
> together, or when a single trope is used repeatedly. Write like a human: varied, imperfect,
> specific.

Specificity is the escape hatch from nearly all of them. A concrete fact carries itself and
needs no rhetorical scaffolding.

## What does not work

- Putting "write in simplified technical English" in a project instruction file. It is
  followed for one session and forgotten the next.
- Asking for a reading level in the abstract. Naming specific banned constructions works.
  "Write simply" does not.
